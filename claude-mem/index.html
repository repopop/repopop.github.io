Avant d'installer

Claude-Mem n'est pas une IA de plus : c'est un plugin qui tourne à côté de ton agent de code. Pendant que tu travailles, un second agent prend des notes (décisions, bugs corrigés, fichiers modifiés), les résume et les range dans une base sur ton PC. La session suivante démarre avec un petit index, et les détails sont lus seulement si besoin. Il te faut un agent déjà installé (Claude Code, Codex, Cursor…) et Node.js. Où l'utiliser :

Dans Claude Code

Dans un terminal : npx claude-mem install (l'installeur trouve tes agents et te demande lesquels équiper). Ou, dans une session Claude Code : /plugin marketplace add thedotmack/claude-mem puis /plugin install claude-mem, et redémarre Claude Code.

Le plus simple

Codex, Cursor, OpenCode + 11 agents

La même commande npx claude-mem install les équipe tous ; pour un seul agent, ajoute --ide (ex. --ide opencode). Windows, Mac et Linux ; sous Windows, Git Bash n'est pas nécessaire.

Une ligne

Copilot CLI, Goose, Roo Code, Warp, Zed

Ils peuvent chercher dans ta mémoire, mais leurs sessions ne sont pas enregistrées (README). Depuis Claude Desktop, tu peux aussi faire une recherche dans ta mémoire.

Recherche seulement

Ce qu'il faut savoir (lu pour toi dans la doc)

  • ↔Et la mémoire de Claude Code ? Claude Code a déjà CLAUDE.md (des consignes que tu écris) et une mémoire automatique, activée par défaut, où Claude note lui-même quelques préférences et corrections. Claude-Mem va plus loin sur 3 points : 1. il enregistre tout ton travail, pas une sélection ; 2. il garde un historique à fouiller (recherche en 3 étapes, page web) ; 3. sa mémoire est partagée entre tes agents (Claude Code, Codex, Cursor, OpenCode…). Les deux peuvent tourner ensemble.
  • €Gratuit, mais qui fait les résumés ? Le plugin est gratuit (Apache 2.0). Les résumés sont faits par un modèle d'IA : ton forfait Anthropic (il consomme ton quota), ta propre clé OpenRouter ou Gemini, ou l'observateur claude-mem payant (30 jours d'essai, moyen de paiement demandé ; après l'essai, retour à ton forfait sauf abonnement). Pour installer sans compte : option --provider ou CLAUDE_MEM_ONLINE_OPTIN=false.
  • ⌂Tes données : la mémoire est dans ~/.claude-mem sur ton PC ; la synchro cloud (cmem.ai) est facultative. Ce que fait ton agent est envoyé au modèle qui résume. Statistiques d'usage anonymes actives par défaut : npx claude-mem telemetry disable. Tout ce qui est entre balises <private> n'est jamais gardé. Les captures d'écran des outils sont gardées par défaut (réglage « Keep images »).
  • !Ça démarre à la 2e session : la mémoire sert à partir de ta deuxième session dans un projet (ou lance /learn-codebase pour pré-charger un projet, environ 5 minutes). Par défaut, le résumé de départ ne montre que l'agent en cours : pour mélanger tous tes agents, active « Include all sources at session start » dans les réglages. Prérequis : Node.js 20.19+ ou 22.12+ ; Bun et uv s'installent tout seuls.
  • ↔Dans la vidéo : « un petit résumé » = l'index de démarrage injecté par Claude-Mem ; le bug de connexion, le jeton expiré et auth.js sont des exemples. « une page web » = le visualiseur local (/viewer et My Work). « une seule commande » = npx claude-mem install. Ne pas lancer npm install -g claude-mem : il n'installe que la bibliothèque.
  • ⚠Le jeton $CMEM : le README présente un jeton crypto créé par un tiers et soutenu par le créateur de Claude-Mem. Il ne sert à rien pour utiliser l'outil ; RepoPop ne conseille aucun achat.

5 usages concrets

01

Reprendre là où tu t'étais arrêté

Le matin, la nouvelle session démarre avec le résumé de la veille : plus besoin de réexpliquer le projet.

Session d'hier→Résumé auto→On reprend
02

Retrouver une vieille décision

« Pourquoi on a choisi SQLite ? » : l'agent cherche dans la mémoire (index, frise, détails) et cite l'observation d'origine.

Ta question→Recherche→Observation citée
03

Ne pas refaire la même erreur

Un bug déjà corrigé ressort dans la mémoire : l'agent ne repart pas sur la mauvaise piste.

Bug corrigé→Noté→Évité ensuite
04

Passer d'un agent à l'autre

Tu commences avec Claude Code et tu continues avec Codex ou Cursor : la mémoire est la même (active « Include all sources » pour le résumé de départ).

Claude CodeCodexCursorOpenCode
05

Relire ta semaine

La page web locale montre les sessions, les observations (bug corrigé, nouvelle fonction, décision) et ton travail en cours.

Note de confiance

8,0/10

Très actif, avec une offre payante

Un projet très suivi et mis à jour presque chaque jour, qui garde ta mémoire sur ton PC ; l'installeur pousse toutefois vers un compte et un observateur payant, et la télémétrie est active par défaut.

Activité du projet 5/5

Version 16.1.3 publiée le 24 novembre 2026 ; le code est modifié presque tous les jours.

Communauté 5/5

Environ 119 500 étoiles et 10 400 copies (forks) ; 46 100 étoiles en avril 2026 (Augment Code).

Respect de tes données 3/5

Mémoire locale et synchro cloud facultative, mais statistiques anonymes actives par défaut et activité envoyée au modèle qui résume.

Modèle économique 3/5

Licence Apache 2.0 ; observateur payant mis en avant à l'installation, et jeton crypto $CMEM soutenu par le créateur.

Maturité 4/5

Créé en août 2025, déjà en version 16 avec des centaines de versions ; les changements fréquents peuvent modifier les réglages.

Comment on note : 5 critères notés sur 5, vérifiés sur GitHub, l'API GitHub, le README et la documentation officielle le 25 novembre 2026. La note sur 10 est la moyenne ramenée sur 10.
